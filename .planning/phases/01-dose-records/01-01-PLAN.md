  <action>
  Before any implementation, write tests describing the desired API. The
  tests MUST fail because `doseStore.ts` doesn't exist yet.

  API to test:
  ```ts
  import { doseStore } from './doseStore'

  doseStore.record({ childId, medicationId, scheduledAt, administeredAt }): AdministeredDose
  doseStore.list(): AdministeredDose[]
  doseStore.listFor(childId: string, options?: { since?: Date, until?: Date }): AdministeredDose[]
  doseStore.clear(): void  // testing helper
  doseStore.subscribe(fn): () => void  // reactive
  ```

  Cases the tests must cover:
  - `record()` returns the saved record with a generated `id`.
  - After `record()`, `list()` includes the new record.
  - `listFor(childId)` filters by child.
  - `listFor(childId, { since, until })` includes records whose
    `administeredAt` falls in `[since, until)`.
  - Records persist across "reloads" — simulate by importing the module
    fresh after writing localStorage, or by calling a `reloadFromStorage()`
    test helper.
  - `subscribe(fn)` fires `fn` when `record()` is called and again on
    `clear()`. Returns an unsubscribe function.
  - localStorage key is `tratament-copii-administered-doses` (additive — must
    not collide with existing three keys).
  - Corrupted localStorage value (invalid JSON) is treated as empty without
    throwing.

  Use `beforeEach(() => doseStore.clear())` to isolate tests.

  Avoid: testing internal storage shape. Tests should treat the store as a
  black box.

<task type="auto">
  <name>Task 2: Implement doseStore to make the tests pass</name>
  <files>src/components/design/doseStore.ts</files>
  <action>
  Implement the smallest version of `doseStore` that turns the failing tests
  green. Mirror the pattern used by `childStore.ts`: a module-scope object
  with internal state, a `Set<Listener>`, and a `useDoses()` React hook
  using `useEffect` to subscribe.

  Specific requirements:
  - Use `AdministeredDose` from `src/types.ts` exactly as defined; do not
    extend it inline. If you discover a missing field, STOP and ask the
    reviewer.
  - `id` generation: `'d' + Date.now().toString(36) + '-' +
    Math.random().toString(36).slice(2, 6)` is fine. Don't pull in `uuid`.
  - Storage key: `'tratament-copii-administered-doses'`.
  - Errors on `JSON.parse` are swallowed with the state initialized to `[]`.
  - Errors on `localStorage.setItem` are swallowed (quota exceeded etc.) but
    state in memory still updates.
  - Export `useDoses()` for component use, but the unit tests target the
    store object directly.

  Avoid: a full reducer pattern. This is a list-append store.
  </action>
