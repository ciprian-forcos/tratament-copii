<task type="auto">
  <name>Task 3: Document test conventions</name>
  <files>.planning/TEST_CONVENTIONS.md</files>
  <action>
  Write `.planning/TEST_CONVENTIONS.md` covering:
  - **Where tests live**: co-located with the unit under test, named
    `<unit>.test.ts` or `<unit>.test.tsx`. Pure logic → `.test.ts`.
    Components → `.test.tsx`.
  - **What to test**: behavior, not implementation. For pure functions,
    assert inputs → outputs. For components, assert rendered output and user
    interactions (using `@testing-library/user-event`).
  - **What NOT to test**: exact pixel positions, font rendering, hardcoded
    SVG path strings, internal component state.
  - **TDD rhythm**: write failing test → confirm it fails for the right
    reason → make it pass → refactor.
  - **Mocks**: prefer real implementations when cheap. Mock `Date.now()` via
    Vitest fake timers when the unit under test reads the clock.
    `localStorage` is real in jsdom — clear it in `beforeEach`.
  - **Coverage**: V1 targets ≥80% line coverage for **new** units (the
    things each plan touches). Not blanket coverage on legacy code.
  - **Running**: `npm run test` (single run, used in PR gate). `npm run
    test:watch` for local TDD.

  Keep this short — one screen of markdown, not a textbook.

  Avoid: prescribing 100% coverage. It produces tests that test
  implementation details.
  </action>
  <verify>
  File exists and is under ~150 lines.
  </verify>
  <done>
  Conventions doc committed.
  </done>
